Description (depositor-authored)

Hydrazine pressure-dependent network, dual-form k(T,P). Chebyshev fits from the Arkane run Final_MRCI_PDep; PLOG fits from the sister run MRCI_davidson_Plog, which is the same network re-fitted with interpolationModel=PDepArrhenius. The two runs label isodiazene differently (H2NN vs NH2N) while pointing at the same Data/NH2N.py and SMILES [N-]=[NH2+]; NH2N was normalised to H2NN before the dual-form build so the 21 channels align. Built with scripts.pdep_ingestion.builder.build_dual_form_request, whose topology check requires both runs to yield an identical (source, sink) channel set.

Per the plan's §7 ruling, network.name/.description are displayed as-is — depositor prose, not curated fact. This disclosure is that labelling: the summary names it as deposited, the title above states only the name itself.

Energy coverage

None of the 9 species entries this network's states are built from carry a deposited thermo (H298) record — measured directly against GET /scientific/species-entries/{ref}/thermo for all 9. A properly-corrected, thermal free-energy surface needs that, so it cannot be drawn from species-level data today, and the diagram below has no energy axis.

That is a different claim from "no energies are deposited on this network" — this network's own solve (nsolve_sfskjknpl7an4uhorhcgpitiv4) separately carries a relative electronic-only energy, referenced to its own lowest state, for all 7 states, and a forward/reverse electronic barrier for 4 of the 21 channels. That is real, deposited data — found against GET /scientific/network-solves/{ref}?include=state_energies,channel_barriers, an endpoint outside this plan's original §1 measurement (see this mock's own README for why that matters). It is an internal modified-strong-collision solver input, not thermo-grade H298, and mixing the two conventions on one axis would misrepresent the surface — so it is shown below as its own disclosure, not folded into a PES.
