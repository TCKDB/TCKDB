# Reaction entry page — implementation plan

Status: draft for builders and reviewers. Base: `main` at `8e0ffeb5`. Plan sibling: `docs/plans/provenance-first-website.md` (items 12–28 define the primitives and review method assumed here).

## 1. Goal and non-goals

**Goal.** Replace the two `RecordPlaceholderPage` routes with a reaction entry page that answers, in one glance: which reaction (equation as the h1, formulas with subscripts, reversible arrow, stoichiometry), which species entries sit on each side (formula links via `SpeciesEntryLink`), which transition-state entries exist and at what stage (`optimized`/… with opt/freq/sp/irc slots), which kinetics records exist with their Arrhenius parameters, fitted T range and levels of theory (an Arrhenius plot mirroring the Cp chart), and whether the entry is admitted to a pressure-dependent network. Plus a thin reaction *identity* page that chooses between entries, and a `/reactions` browse tab, and a `tckdb get reaction <ref>` CLI verb. Every fact on the page is a served value; nothing is inferred from absence.

**Non-goals.** No network page (`/networks/:ref` stays a link to nothing until its own slice), no PLOG/Chebyshev surface plot (those records are listed, not plotted), no reaction-family curation, no atom-map visualisation (badge only), no review/editing flows, no changes to upload paths, models, or migrations, no re-ranking of kinetics beyond the served D9 order.

## 2. Information architecture

**Correction to the brief.** `GET /scientific/reaction-entries/{ref}/full` already exists (`backend/app/api/routes/scientific/provenance.py`, service `get_reaction_full`, schema `scientific_provenance.py`), with legal include tokens `species, kinetics, transition_states, atom_map, calculations, path_search, irc, scans, conformers, artifacts, review, trust, internal_ids, all` and a default set of `species,kinetics,transition_states`. `tckdb_client.get_reaction_full` already wraps it. The API work in §3 is additive on that surface, not a new endpoint.

**Route key.** Two routes, mirroring species vs species-entry:

- `/reactions/:reactionRef` takes the identity `rxn_…` and is a chooser, like `/species/:speciesRef`. Justification from live data: `rxn_naeqmg4l5wyqex5cl5tir2vt2y` (NN ⇌ H2 + N2H2) has four `rxe_` entries from four deposits; the site rule is "never merge or silently choose between matching entries". Both existing inbound links (`TransitionStateBrowseRow.tsx`, `TransitionStateEntryPage.tsx` "Reaction record") already pass `rxn_`, so they land correctly with no change. Data: `reactions/search?reaction_ref=rxn_…` (exists; returns every entry with `availability` flags and review badge).
- `/reaction-entries/:entryRef` takes `rxe_…` and is the record page, fed by `/full`. An `rxe_` handed to `/reactions/` redirects by prefix check (no request), the same self-healing pattern `BrowsePage` uses for `?kind=`.

**Entry page sections, in order** (each is a `SectionHeading` inside `PageShell`; four or more sections so the side ToC appears):

1. **Identity header** — `RecordIdentityHeader` with kicker "Reaction entry · deposited scientific record", review pill, `titleVariant="display-2"`, title = `ReactionEquation` (new component, §4), `ownRef` = the `rxe_` ref with copy button. Identity `.kv-list`: reaction identity `rxn_` (link to chooser), family (`not recorded` when null — live hydrazine entries have `family: null`), reversible yes/no, atom map badge from `reaction_entry.atom_maps` (`[]` → "no atom map deposited"). `RefsDisclosure` holds related refs only.
2. **Participants** — one `.data-table` per side (reactant/product): formula link (`SpeciesEntryLink` with `species_entry_label` chip, e.g. the Z entry of N=N), SMILES in data face, stoichiometry, participant review pill. Data: `species` section.
3. **Evidence on this entry** — `EvidenceChecklist` below the metric row (rule from item 18): kinetics records (count), transition-state entries (count), atom map, path search/IRC (from TS `evidence_summary`), network membership. Counts of served arrays only; "0" is stated as "none deposited", never "none exist".
4. **Kinetics** — one card per `KineticsRecord` in served order: model kind, origin, A (with `A_units`), n, Ea, T range, uncertainty block, tunnelling, degeneracy convention, `evidence_completeness` as a checklist, provenance (`primary_level_of_theory`, software, workflow tool, literature), `ProductLevelsFact` (§3 `levels`), the `network_kinetics_ref` bridge when non-null, link to `tse_` used. Then the Arrhenius chart (§4) with its table equivalent. `[]` → "No rate coefficient has been deposited for this reaction entry." (about the archive, not the chemistry). PLOG/Chebyshev/falloff blocks render as a `Disclosure` with their table, never plotted.
5. **Transition states** — one row per `TransitionStateInFull`: link to `/transition-state-entries/:ref`, status pill (`optimized` etc.), review pill, slots `ts_opt/ts_freq/ts_sp/ts_irc/ts_guess` as calculation links, `evidence_summary.levels_of_theory` rendered through `ProductLevelsFact` (opt→geometry, freq→frequency, sp→energy) collapsing to one fact when equal (item 25). `dependencies[]` feed `CalculationDependencyGraph` with `dependencyWording.ts` labels only when edges are served; no arrows inferred from type.
6. **Pressure-dependent network** — from the `networks` section (§3): name, `net_` ref, solve T/P range, channel count. Three states: key absent → section not rendered (not requested / older API); `[]` → "No pressure-dependent network in this archive admits this reaction entry."; populated → list. Cite item 14's "IRC ran, endpoint identity not deposited" and the `/full` docstring's three-state rule as the wording precedent.
7. **Review** — `review_summary` counts as pills; `review_records` only when `include_review=full` (not requested by the page; omitted key renders nothing, per the plan's clarification on omitted vs null).

**Identity page (`/reactions/:reactionRef`)**: equation h1 (from the first entry's participants), family, reversible, then a `.data-table` of entries: `rxe_` link, deposited date, has kinetics / has TS / kinetics count (served booleans), review pill. Mirrors `SpeciesOverviewPage`'s grouped chooser without grouping (entries differ by deposit, not by state).

**Browse (`/species?kind=reaction`)**: a fourth `BrowseKind` in `browseApi.ts`, rows = `ReactionBrowseRow` (equation with formulas, family, review pill, has-kinetics/has-TS pills, stretched link to `/reaction-entries/:ref`). Filters the API already supports on `reactions/search`: reactant SMILES, product SMILES, family (dropdown from `/meta/reaction-families` via `vocabApi.ts`), `min_review_status`. Requires the browse endpoint in §3 because `reactions/search` rejects an unscoped request (`missing_reaction_search_filter`, verified live).

## 3. API work (all additive; no schema or migration change)

Files: `backend/app/schemas/reads/scientific_provenance.py`, `backend/app/services/scientific_read/provenance.py`, `backend/app/schemas/reads/scientific_kinetics.py`, `backend/app/services/scientific_read/kinetics.py`, `backend/app/api/routes/scientific/_response.py`, new `backend/app/api/routes/scientific/reactions_browse.py`, `backend/app/services/scientific_read/reactions.py`, `backend/app/api/routes/scientific/__init__.py`.

**A. `/full` participant enrichment.** Add `formula: str | None` and `stoichiometry: int` to `ReactionFullSpeciesParticipant` (and to `ReactionParticipantSummary` in `scientific_reactions.py` so search rows can render formulas). Formula via the existing RDKit-cartridge expression (`species.py::_formula_expr`, the one item 19 said to share on its next copy); stoichiometry from `chem_reaction.reaction_participant.stoichiometry` joined by `(reaction_id, species_id, role)`. No new column.

**B. Kinetics `levels`.** Add `levels: ScientificLevelsSummary` (already defined in `scientific_common.py`) to `KineticsRecord`, always present, derived from the TS chain the provenance already resolves (`ts_opt`→geometry, `ts_freq`→frequency, `ts_sp`→energy with `energy_source="sp"`, else opt). Reuse `app.services.calculation_levels.derive_levels` by feeding it role links built from those three calcs. Note `KineticsCalculationRole` is `reactant_energy/product_energy/ts_energy/freq/irc/…`, not opt/freq/sp, so this is a mapping, not a direct call — document it in the field docstring. Reactant/product energy levels stay per-record facts (§7).

**C. `include=networks` on `/full`.** New section `networks: list[ReactionFullNetworkMembership] | None` — `{network_ref, name, solve_temperature_min_k, solve_temperature_max_k, solve_pressure_min_bar, solve_pressure_max_bar, channel_count, review}` — built from `network_reaction` rows for the entry, reusing the summary builder in `services/scientific_read/networks.py`. Register the token in `_LEGAL_INCLUDE_TOKENS`, `_DEFAULT_INCLUDES` (so the page needs one request), and `REACTION_FULL_SECTIONS` (so the absent/null/populated contract holds; `test_unrequested_sections_are_absent.py` will demand it). Until deployed, the frontend falls back to `networks/search?reaction_entry_ref=…&include=reactions` (verified live: the hydrazine network lists six `rxe_` refs).

**D. `GET /scientific/reactions/browse`.** Same shape as `reactions/search` but no filter required; filters `family, reactant_smiles, product_smiles, has_kinetics, has_transition_state, min_review_status, include_rejected, include_deprecated, offset, limit`; default sort L3. Own route file (mirrors `transition_states_browse.py`); the service gets a `browse_reactions` entry that skips the `missing_reaction_search_filter` gate and shares the query builder.

**Sketched `/full` response delta** (existing keys unchanged):

```
reaction_entry: {reaction_entry_ref, reaction_ref, equation, reversible, family, review, atom_maps[]}
species: {reactants[]: {species_entry_ref, species_entry_label, smiles, +formula, +stoichiometry, participant_index, review}, products[]: same}
kinetics[]: KineticsRecord + levels{geometry, frequency, energy, energy_source}
transition_states[]: {transition_state_ref, transition_state_entry_ref, status, review, evidence_summary{levels_of_theory{opt,freq,sp,irc}}, calculations{ts_opt,ts_freq,ts_sp,ts_irc,ts_guess}, dependencies[]}
+networks[]: {network_ref, name, solve_*_k/bar, channel_count, review}
review_summary, request{include[], include_review}
```

**Regen steps per API PR:** `UPDATE_OPENAPI_GOLDEN=1 conda run -n tckdb_env pytest tests/api/test_openapi_snapshot.py` and review the diff; no new error codes, so `code_catalogue.py`/`test_api_code_catalogue.py` need no entry (if the browse route adds one, it must be catalogued); `schema.dbml` is untouched because no ORM model changes — state that in the PR and do not run `scripts/generate_dbml.py`; Python client: add `browse_reactions` and the new typed fields in `scientific_types.py` so `test_openapi_parity.py` / `test_typed_parity_methods.py` stay green.

## 4. Frontend work

Files (new unless noted): `frontend/src/pages/ReactionEntryPage.tsx`, `pages/ReactionOverviewPage.tsx`, `api/reactionEntryApi.ts`, `api/reactionOverviewApi.ts`, `components/ReactionEquation.tsx`, `components/ReactionKineticsSection.tsx`, `components/ReactionTransitionStatesSection.tsx`, `components/ArrheniusChart.tsx`, `domain/arrhenius.ts`, `domain/arrheniusChartLayout.ts`, `domain/reactionEquation.ts`, `reaction-entry.css`, `arrhenius-chart.css`, `components/ReactionBrowseRow.tsx`; edited: `App.tsx`, `api/browseApi.ts`, `components/BrowseFilterForm.tsx`, `components/BrowseKindSelector.tsx`, `pages/BrowsePage.tsx`, `browse.css`, `pages/RecordPlaceholderPage.tsx` (drop `reactionRef`).

**Data loading.** `loadReactionEntry(ref)` requests `/full?include=species,kinetics,transition_states,calculations,networks` once via `requestScientificJson` + `useScientificRecord` (dedup cache from #370). Zod schemas use `.passthrough()` and mark `formula`, `stoichiometry`, `levels`, `networks` optional so a pre-deploy API parses; `levels` resolves through `resolveProductLevels` with the fallback path deriving from `provenance.ts_*_calculation_ref` looked up in the `calculations` section (test that both paths render identically, as item 25 did).

**Reaction equation.** `reactionEquation.ts` builds sides from `species.reactants/products` sorted by `participant_index`, collapsing repeated identical `species_entry_ref` on one side into a coefficient (exact, not a guess) and multiplying by `stoichiometry`; `ReactionEquation.tsx` renders coefficient, `SpeciesEntryLink` (formula subscripts via `Formula`, SMILES data-face fallback when formula is null), `species_entry_label` chip, `+` and arrow (⇌ for reversible, → otherwise, with `aria-label`), a `<wbr>` after every `+` and arrow (the TS page's `renderEquationWithBreaks` rule, promoted into this component so both pages share it).

**Arrhenius chart spec.** Same skeleton as `ThermoCpChart.tsx`: hand-rolled SVG, `chartScale.ts` (`linearScale`, `domainWithPadding`, `formatTicks`), `seriesColor` and legend/absence-note structure lifted from `thermoCpChartLayout.ts` into shared helpers only if untouched by other slices (otherwise duplicate one function and note it). x = T (K), linear, over the union of fitted ranges; each curve drawn only within its own `record_min_k..record_max_k`; y = log10 k with axis label built from `A_units`. `arrhenius.ts`: `k(T) = A·T^n·exp(−Ea/(R·T))`, R = 8.314462618×10⁻³ kJ mol⁻¹ K⁻¹, `multi_arrhenius` summed over terms, ~60 samples per curve. One panel per distinct `A_units`; records with `plog_entries`, `chebyshev`, `falloff`, or third-body flags are excluded with an absence note naming the ref and the reason. Tokens only (`--accent`, `--ink`, series colours as in the Cp chart); reduced-motion safe (no animation). Accessible equivalent: a `.data-table` behind a `Disclosure` with T at the axis ticks × log10 k per record, `<caption>` naming units; the SVG has `role="img"` and a visually hidden summary sentence. Legend chips carry `kinetics_ref` in the data face.

**Browse.** `BROWSE_KINDS` gains `"reaction"`; `buildReactionBrowseQuery` maps filters to `/reactions/browse`; `clearInapplicableFilters`/`hasActiveFilters` extended; `browseEmptyState.ts` wording for the kind. `BrowseFilterForm` shows reactant/product SMILES inputs and the family dropdown for this kind only.

## 7. Risks and open decisions for the owner

- **Route key**: two routes as above, or one `/reactions/:ref` accepting both prefixes. The plan recommends two; the cost is one more chooser page.
- **Levels on kinetics**: the TS chain gives three levels; reactant/product energies (`reactant_energy`/`product_energy` roles) may sit at another level. Proposal: TS levels are the "three levels" case; reactant/product levels are per-record rows shown only when served and different. Live oddity: `kin_spkzatwjlvmmnja3i5im4fl7hq` reports `ts_opt_calculation_ref: null` while its TS entry has `has_opt: true` — the kinetics provenance resolver and the TS evidence disagree; the page must show what each serves, and the owner should decide whether the resolver is fixed in PR 1.
- **Network-only reactions**: a reaction admitted to a network as a `network_reaction` but with no `kinetics` row (all 20 hydrazine entries today). Proposal: kinetics section says "No rate coefficient deposited on this entry; phenomenological k(T,P) for this system is served by network `net_…`" with a link, never rendering channel kinetics as if they were this entry's.
- **"Not reviewed" for a reaction entry**: `reaction_entry.review` is the entry's own badge; `review_summary` counts every joined record. Proposal: pill = entry badge; summary counts under Review with the sentence "counts cover every record joined into this page".
- **Undefined in the read spec**: `stoichiometry` on entry participants is not in `read_api_mvp.md`; the `equation` string is SMILES-only by contract, so the h1 is rendered from participants and the served string is shown once in the data face; `include=networks` is a new token (L4 enumerates tokens, so the MVP spec needs a line).
- **Rate limit**: one `/full` request per page plus one `networks/search` fallback until PR 1 deploys; the identity page adds one `reactions/search`. Stay under three per navigation.
