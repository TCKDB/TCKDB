## Decision and scope

Token: `formation_from_elements_298k`. It names formation from elemental reference forms and the pinned temperature; its definition specifies 298.15 K exactly. H(T) adds only the species thermal increment to formation enthalpy at 298.15 K.
The owner revised the initial scalar iff proposal: the database implication is one-way, and workflows require a declaration exactly when any scalar, point enthalpy, Wilhoit h0 or NASA enthalpy content exists. Fit-only deposits need no scalar, and no scalar is synthesized.
No data step, origin default, reference inference, accepted-science repair, production access, frontend change or mechanism-file export behavior change is included. The 0 K formation column is unchanged.
The previously ignored workspace copies of `docs/unit_policy.md` and `docs/schema_analysis.md` are now tracked so their binding statements are reviewable in this PR.

## Reproduction before edits

1. At the original base, `backend/app/db/models/thermo.py:40` claimed formation semantics, but its column list and CHECKs had no reference declaration. ## Issues found and settled during verification

- The initial rest run caught a downgrade naming-convention defect. Using `op.f` prevents the constraint name from being prefixed twice; the migration test exercises the application naming metadata.
- The initial API run exposed the SDF adapter as another producer of undeclared enthalpy. It now requires explicit configuration; the bulk fixtures declare their convention and a new assertion prevents parse errors from turning those uploads into silent skips.
- The initial scientific run caught a declaration passed to an unrelated export helper and an undeclared Wilhoit fixture. Both fixtures were corrected while preserving their numerical assertions.
- ARC previously fabricated h298=0 when only a fit was present. It now retains null; a regression and a killed mutation protect that behavior.
- CCCBDB sensible-only input now produces an observation without an empty thermo payload. Its value and raw source datum remain intact.
- The CHEMKIN adapter suite caught its separately stored module version still at 0.3.0. It is now 0.4.0, matching package metadata; the full adapter suite passed on rerun (55 passed, one pre-existing opt-in live-upload skip). No live upload was enabled.
- The final branch includes main's Phase D changes; earlier gate runs before that integration are not claimed as the final verification.

No unresolved implementation or verification issue remains. The opt-in live upload was outside this task and was not enabled.
