# TCKDB landscape and publication audit

Assessment date: 2026-09-18. This is an evidence and research-design audit, not a claim that the proposed experiments have been run.

## Decision

TCKDB's strongest near-term scientific contribution is an integrated, inspectable lifecycle for **computed gas-phase thermochemistry and kinetics**: chemical identity → calculation evidence → derived products → attributed review and selection → reproducible releases and executable exports. The long-term opportunity is a common discovery and evidence layer across existing resources, with domain-specific models behind it. A claim to replace all thermochemical databases would be scientifically weaker and operationally much larger than either contribution.

Leadership should mean that a researcher can discover relevant evidence, understand disagreement, select a fit-for-purpose result, and reproduce the selection with one coherent workflow. It need not mean owning every source, reproducing every specialist evaluation method, or converting every domain to a molecular property table.

The existing manuscript contains promising demonstrations, but several competitor claims are contradicted by primary documentation. The immediate publication priority is stronger evidence and a narrower claim, alongside the implementation improvements assessed by the companion code audits.

## Corrections to the current narrative

1. **Replace the abstract's universal “existing resources store the number and a citation” claim.** ATcT has network provenance; ThermoML has structured experimental context; QCArchive has computational records. The defensible question is whether TCKDB makes a particular end-to-end thermo/kinetics workflow easier to inspect and reproduce.
2. **Correct the RMG disagreement cell.** The documented all-thermo query returns competing parameter sets and sources. A narrower question is whether independent computational deposits, artifact custody, and attributed review are represented with the lifecycle TCKDB provides. That requires a feature-level comparison, not a dash for multiple values.
3. **Correct the ThermoML access description.** XML is not its only machine interface: JSON, metadata REST search, and versioned bulk distribution exist. Avoid implying the metadata API returns all numerical data points. [NIST architecture paper](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=933505)
4. **Drop “only TCKDB combines all eight” until the comparison is operationalized and independently checked.** Several columns bundle unrelated capabilities, such as API access and self-hosting. Split them; cite a source for every positive and negative assertion; use “not evaluated” where the evidence is incomplete.
5. **Do not equate structured provenance with re-computation.** A full dependency graph can still omit correction constants, solver settings, executable versions, environments, licensed software, or actual retrievable artifacts. Separately measure lineage completeness, post-processing replay, and fresh electronic-structure reruns.
6. **Do not equate evidence completeness, approval, precision, accuracy, or agreement.** A richly documented calculation can be systematically inaccurate. Seven matching submissions from one workflow are useful deposit-history evidence, but not independent external replication or scientific accuracy validation.
7. **Treat MCP as an access convenience unless a specific scientific retrieval experiment shows additional value.** The manuscript's first/only MCP claim is time-sensitive and unverified here. It should not carry novelty.
8. **Reconcile the draft with the existing divergence audit.** That audit reports that lossless restoration belongs to an archive export rather than the scientific NDJSON stream; reaction-level PLOG/Chebyshev and broader statmech vocabulary already exist; the public browsing frontend and search-time trust filters exist; and review-state wording and corpus counts changed. Recheck against the chosen release before editing the manuscript.
9. **Avoid “none of these gaps is architectural.”** Experimental measurement models, covariance structures, solution conventions, crystals, and CALPHAD phases require actual semantic design. They cannot be shown compatible with the current schema merely by saying they could be another result row.

## Community needs and the order to address them

The following needs are an inference from the verified fragmentation and the local manuscript, not a survey-based measurement of community priorities. Validate the ordering through independent mechanism builders, data evaluators, quantum-chemistry contributors, and ML users.

| Need | Concrete outcome | Why it should precede breadth |
|---|---|---|
| Reusable scientific evidence | A user can trace a result to accessible inputs, outputs, transformations, and exact software/settings, or see an explicit missing-evidence reason. | More imported values do not repair an incomplete derivation. |
| Comparable quantities | Queries distinguish phase, reference state, standard state, temperature, pressure, composition/bath gas, identity, and evidence class. | A fast cross-source query can otherwise compare different physical quantities. |
| Dependence-aware uncertainty | Reported uncertainty meaning, coverage factor/distribution, shared sources, coefficient covariance, and propagation are represented explicitly. | Multiple databases can repeat the same evidence; treating copies as independent creates false precision. |
| Stable scientific citation | A release pins records, source versions, review state, selection policy, and artifact digests; a reader can reproduce it after the live service changes. | A living database needs reproducible scientific reference points. |
| Practical contribution and review | Independent groups can deposit complete records, repair rejected submissions, review evidence, and cite their contribution with reasonable effort. | Community adoption depends on workflow cost and credit, not just schema expressiveness. |
| Downstream numerical fidelity | Thermo functions and rates survive supported exports over their stated domains, with explicit rejection of unsupported cases. | A file that parses can still encode numerically wrong chemistry. |
| Representative coverage | Published coverage by element, charge, spin, size, reaction family, method, temperature/pressure, and review state. | Honest coverage maps reveal where the database is actually useful. |

ATcT and TRC establish that evaluation and uncertainty are substantive scientific work, while RMG demonstrates the value of connecting data to model construction. TCKDB should integrate those lessons and expose what has actually been validated. [ATcT](https://atct.anl.gov/), [TRC](https://trc.nist.gov/), [RMG](https://rmg.mit.edu/)

## A practical federation strategy

**First complete the molecular vertical.** Pin a small set of thermochemistry and kinetics use cases, with RMG/Cantera interoperability, accessible computational evidence, and release reproduction. Add one external reference comparison with a pinned source release and a demonstrable state/identity mapping. A manually curated, rights-cleared reference subset is scientifically useful before a complete automated connector exists.

**Then pilot experimental molecular data.** Import a narrow ThermoML property class with experimental method, sample/composition, conditions, uncertainties, citation, and original source record. Mark unsupported semantics explicitly. Preserve reported observations separately from fitted models and recommended values. Prove a round-trip before expanding properties and sources. ThermoML already provides the relevant exchange machinery. [Archive](https://trc.nist.gov/ThermoML/Browse), [schema uncertainty publication](https://www.nist.gov/publications/thermoml-xml-based-approach-storage-and-exchange-experimental-and-critically-1)

**Federate discovery before scientific reconciliation.** A source registry and cross-reference service can connect records while preserving distinct quantities. Mapping two identities is a different operation from transforming units; transforming units is different from converting standard states; and those are different from statistically reconciling estimates. Each should create a typed, versioned, inspectable transformation with preconditions and failure reasons.

**Add cross-domain packages when a real use case warrants them.** Crystals need structure/phase identity, solutions need composition and activity conventions, and CALPHAD needs phase-model parameters. A shared provenance and release envelope can connect these packages without pretending their scientific entities are interchangeable. OPTIMADE provides a useful federation precedent; pycalphad shows the distinct model objects involved. [OPTIMADE](https://www.optimade.org/specification/latest/), [pycalphad](https://pycalphad.org/docs/latest/api/pycalphad.io.html)

**Make probabilistic reconciliation a separate research milestone.** Store observation dependence before fitting a reconciliation model. Evaluate posterior calibration, sensitivity to priors, duplicated evidence, shared correction schemes, and inconsistent constraints. Value-of-information or autonomous calculation prioritization should follow that validation. It is not a credible near-term implication of simply having a provenance graph.

## Testable claims and experiments

All experiments below are proposed. None of their outcomes, numerical thresholds, or sample sizes should be described as existing results.

| Claim | Experiment and comparison | Reported metrics and failure cases | Acceptance evidence |
|---|---|---|---|
| C1: Independent contributions remain distinguishable without fragmenting chemical identity. | Deposit a fixed adversarial corpus containing equivalent representations, stereo/isotope/spin variants, radicals, resonance forms, conformers, and TS candidates through independent paths. Compare a simple canonical-identifier baseline. | False merges, false splits, unresolved identities, expert adjudications, and performance by identity class. | Publish fixtures and expected relations; no known incorrect merge in the release corpus. State coverage limits. |
| C2: Stored evidence supports independent scientific replay. | A contributor-independent reader reconstructs selected thermo and kinetics products from a frozen archive in a clean environment. Compare flat exported coefficients and archive-plus-manual-files workflows. | Fraction reconstructable, missing dependency categories, preparation time, and numerical deviation in H/S/Cp and k(T,P). Separate post-processing from fresh electronic-structure reruns. | Every claimed replay result has a script, environment, input manifest, tolerance rationale, and output artifact. Failed cases remain in the denominator. |
| C3: Exports preserve supported scientific behavior. | Import and export several mechanisms spanning rate-law and thermo families, then evaluate both versions with a pinned independent interpreter on a grid within validity domains. | Absolute and relative errors in Cp/H/S, forward/reverse rates and equilibrium constants; behavior at polynomial boundaries, low rates, falloff limits and duplicate reactions. | Predeclare tolerances tied to precision and transformations. Parsing success alone does not pass. Record unsupported forms and exclusions. |
| C4: Review and selection are reproducible and distinct. | Freeze conflicting candidate sets, review events and policy versions; repeat selection and restore after later review/supersession changes. Compare latest-only, most-reviewed and completeness-only baselines. | Repeatability, explained selection changes, validity-range violations, proportion receiving no eligible result, and external accuracy separately from review rank. | Exact reproducibility for fixed inputs, plus explicit refusal when no eligible candidate exists. No claim that completeness predicts accuracy without data. |
| C5: Methodological disagreement is scientifically informative. | Collect the same molecular/reaction targets from genuinely different methods and independent groups; compare to a pinned external reference and examine thermal/correction/rotor choices. | Method-specific bias/error, uncertainty coverage, agreement conditional on shared sources, and cases whose disagreement is explained by recorded choices. | Identify which references overlap calibration/training or share raw evidence. Count methods/groups, not repeated upload IDs, as independence evidence. |
| C6: Uncertainty propagation improves decision reliability. | On a small explicit network, compare diagonal-only uncertainty with shared-source/coefficient covariance and analytic or Monte Carlo propagation. Include synthetic cases with known ground truth and held-out measured constraints. | Interval coverage, calibration, cycle residuals, sensitivity to dependence assumptions, and misleading narrowing caused by duplicate evidence. | Validate on cases with known covariance before claiming ATcT-like reconciliation. This is a later-methods claim if the machinery is not implemented. |
| C7: The workflow is usable outside the author team. | Independent groups deposit, inspect, correct, export and reproduce predefined tasks without maintainer editing of their scientific records. | Completion rate, time, rejected submissions, support interventions, review agreement and reasons for abandonment. | Publish protocol and deidentified task outcomes; distinguish formative interviews from a powered user study. |
| C8: Live exports improve ML dataset hygiene. | Construct random, chemical-family, and provenance-grouped splits from a frozen corpus; compare duplicate-aware lineage grouping against identifier-only grouping. | Leakage rate, connected source-group sizes, performance changes and uncertainty calibration. | Publish split membership and grouping rules. Do not promise improved predictive performance from provenance alone. |

The minimum strong first-paper bundle is C1–C5 with at least a modest external-user exercise from C7. C6 and C8 can become later papers; they should not block a tightly scoped infrastructure article if clearly labeled future work.

### Ablations that identify the value of TCKDB's design

- **Remove structured derivation links:** retain values and files but replace links with prose; measure replay completion and time.
- **Remove review/selection separation:** reduce status to one preferred flag; measure whether old decisions can be reproduced after new evidence arrives.
- **Remove source lineage:** count copied or shared evidence independently; quantify resulting false confidence or ML leakage on a controlled example.
- **Remove scientific-state constraints:** allow matches on molecule/property alone; quantify incorrect comparisons using deliberately incompatible phase/state examples.
- **Remove raw primitives:** retain frequency lists or fitted coefficients only; repeat a predefined reanalysis requiring a Hessian or original fit data.

These are proposed internal design ablations, not claims that a named competing system necessarily lacks each feature. Compare competitors using configurations they actually support.

## Publication scope and evidence gates

**Recommended first article:** a software/data-infrastructure contribution centered on the molecular evidence-to-product lifecycle. Its scientific result should be the demonstrated ability to preserve, inspect, reproduce, and reuse chemically meaningful products across contributions and downstream tools. Database breadth, test counts, schema size, and an MCP interface can support that argument but cannot substitute for it.

**Possible later dataset article:** a substantively useful, validated, frozen multi-method molecular thermo/kinetics corpus with uncertainty and accessible artifacts. Scientific Data distinguishes repository/standards Articles from Data Descriptors. The latter require dataset records, technical validation, availability and code statements; reviewer access and public repository deposition have explicit requirements. Match the manuscript type to the actual output. [Submission guidance](https://www.nature.com/sdata/publish/submission-guidelines), [data policies](https://www.nature.com/sdata/policies/data-policies)

**Possible later methods article:** dependence-aware reconciliation or value-of-information-guided computation, only after predictive or calibration benefits have been demonstrated against suitable baselines.

| Gate | Deliverable before making the associated paper claim | Present evidence in this audit |
|---|---|---|
| G1: Auditable scope and prior art | Feature definitions, per-cell sources, exact inspected versions, and a bounded novelty statement. | Not closed: current abstract/table overstate competitor limitations. |
| G2: Frozen reproducibility package | Tagged code/client/adapters, schema/migrations, archive, source manifests, environment lock, checksums, analysis scripts and citable repository release. | Not closed by the manuscript's promise to freeze later. No release was created in this audit. |
| G3: Correct manuscript-to-release correspondence | Regenerate corpus and capability statements from the frozen package; reconcile every material item in the September divergence audit. | Not closed: current draft and audit conflict in export, review, rates, frontend, and counts. |
| G4: Scientific validation beyond API correctness | C1–C5 outputs with tolerances, failed-case denominators, multiple methods and independent scrutiny. | Partial historical demonstrations only; no fresh validation run here. |
| G5: Actual curation | Approved/withdrawn/superseded examples with attributed rationale and reproducible selected releases. | September 13 audit reported zero approved records and zero releases at that time; current state must be rechecked. Infrastructure is not evidence of community validation. |
| G6: Accessible evidence | Reviewer can anonymously obtain the publication package and artifacts supporting claims, subject to documented rights; live service access limitations explained. | September audit says artifact download needs authentication. A separately archived publication package may satisfy reproducibility without changing all live-service access. |
| G7: Sustainable operation | Named ownership, backup/restore evidence, retention and deprecation policy, contributor credit, review governance, and a realistic service support plan. | Not evaluated here. Avoid declaring durable community stewardship solely from a deployed URL. |

FAIR includes persistent identification, provenance, reusable metadata and clear licenses; it does not require every live datum to be anonymously accessible. Distinguish FAIR design claims from the practical access promised for this publication. [FAIR principles](https://doi.org/10.1038/sdata.2016.18)

Suggested paper framing: **“TCKDB: reproducible evidence and curation for computational thermochemistry and kinetics.”** The long-term federation roadmap belongs in the discussion, with explicit domain boundaries and unsolved uncertainty/governance problems. The first paper should establish a trusted foundation on which the broader offering can credibly grow.
