# Store artifacts verbatim; gate raw-log access rather than scrub at rest

Calculation artifacts (electronic-structure log files) are stored byte-for-byte and content-addressed by SHA-256; the stored bytes are never rewritten. Redacting personally-identifying or infrastructure strings — scratch paths, usernames, cluster hostnames, scheduler job IDs — at upload would break content-addressing, because the hash would no longer match the producer's original file, and with it the end-to-end, re-runnable traceability the four-role model promises. Scrubbing is therefore never applied to bytes at rest, and contributor-side scrubbing is not relied upon.

The exposure those strings create lives only in the raw artifacts, not in the queryable science: parsed products — energies, geometries, levels of theory, and the execution-parameter vocabulary — are derived by extracting scientific content and carry no scratch paths or identities. That parsed layer is the public face of the database. Raw-artifact download is therefore an access-controlled operation, served only to authorized callers, so that unredacted logs never reach anonymous clients; retrieval of raw bytes remains verifiable against the stored SHA-256.

**Amended 2026-08-24.** This record originally said raw download was "served only to authorized callers **and gated by review status**". The authorization half is the argued part and stands unchanged: the gate is unconditional, no deployment can opt out of it, and no download path is anonymous. The review-status half was asserted rather than argued, and it turned out to be the wrong gate. Curator approval publishes evidence to *everyone* authenticated; it is not a statement about who may see their own upload. Measured on the hosted instance that day, 563 of 563 stored artifacts belonged to calculations still `not_reviewed`, so an approval-only gate had never opened once — locking depositors out of the files they had themselves deposited. Authorized now means **approved, or deposited by the caller**, where ownership is the rule the upload path already authorizes attachment with (`submission.created_by`, falling back to `calculation.created_by` for pre-submission deposits; see [ADR 0018](0018-an-update-names-what-a-submission-owns-and-proves-it-unchanged.md)). Nothing above about verbatim storage, content-addressing, or scrub-at-egress is affected.

Where raw logs must be exposed beyond authorized callers, redaction happens at egress, never at rest: a scrub-on-download mode returns a clearly-labelled redacted copy whose bytes intentionally differ from the stored hash, rather than the verbatim artifact. This is an explicit, opt-in egress transform and never the default, because heuristic redaction is lossy and cannot be trusted to catch every identifier; it supplements, and never substitutes for, access control at the database boundary.
